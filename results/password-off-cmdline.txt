Harness fix: the APP password no longer appears on any command line (host or prm3)

Before: wl.sh ran `sqlplus -s -L "app/<password>@<descriptor>"` every second on prm3 (readable by any local user
with ps); check.sh put the password into the ssh command string (`export APP_PASSWORD='...'`) and into
`sqlplus 'app/<password>@...'` inside another ssh command (visible in ps on the host and on prm3).
After: sqlplus starts with /nolog and CONNECT comes on stdin; ssh runs `bash -s` with a here-document.

Test (scenario dg-a, short workload through check.sh — harness_pwfix_t0..t3 in results/raw):
  check.sh harness_pwfix_t0 / t1 / t2 / t3 : RESULT: PASS each, client errors A=0 B=0
  100 ps samples on prm3 during the workload : sqlplus processes seen = 8, lines containing the password = 0
  ps on the host during the workload          : lines containing the password = 0
Cleanup in the documented order (Replicats at EOF -> STOP -> drop_txn.sql -> START), GoldenGate running both ways.
